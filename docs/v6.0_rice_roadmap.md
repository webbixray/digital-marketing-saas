## 📊 RICE Scoring Reference

| Dimension | Scale | Description |
|-----------|-------|-------------|
| **Reach** | 1-10 | Users affected in next quarter (10 = 100% of agency users) |
| **Impact** | 0.25 – 3 | Per-user impact (0.25=minimal, 3=massive) |
| **Confidence** | 50/80/100% | Certainty in estimates |
| **Effort** | Person-months | Engineering time (PM + QA + deploy) |

**RICE = (Reach × Impact × Confidence) / Effort**

## 🏆 Tier 1 — Ship First (RICE > 150)

### 1. Multi-Tenant Data Integrity & Index Repair
| Field | Value |
|-------|-------|
| **RICE Score** | **336** |
| **Reach** | 10 (every agency/user affected) |
| **Impact** | 2 (prevents data corruption, 10-100x query speedup) |
| **Confidence** | 100% (audit proven) |
| **Effort** | 0.5 PM |

**Why Now:** 8 critical + 12 high-priority issues in migration audit. Orphan records, missing FK constraints, and absent indexes are production risks. This is non-negotiable infrastructure.

**Technical Approach:**
1. **Fix FK constraints** — Add `->constrained()->nullOnDelete()` to `invoice_items.invoice_id`, `campaign_post.social_post_id`, `content_insights.social_post_id`
2. **Fix data types** — Migrate `integer()` columns to `foreignId()` in `social_posts` (`approved_by`, `client_id`), `roles.agency_id`
3. **Add missing `agency_id`** — `notifications`, `workflow_logs`, `workflow_webhook_logs` with FK + cascade
4. **Add FK indexes** — `social_post_scheduled_logs.social_post_id`, `support_ticket_replies.ticket_id/user_id`, `activity_feeds.user_id`, `ai_credit_purchases.agency_id`
5. **Add composite indexes** — `['agency_id','status','created_at']` on `social_posts`, `['agency_id','type']` on `custom_templates`, `['agency_id','action']` on `activity_logs`
6. **Fix unsafe migration** — Wrap `update_plan_limits` in chunked transaction
7. **Add unique constraints** — `custom_templates[agency_id,type,name]`, `email_templates[agency_id,slug]`

**User Impact:** Eliminates data corruption risk. Dashboard loads 5-50x faster. Required for enterprise sales (SOC2 readiness).

**Deliverable:** `2026_09_25_000000_v6_database_repair.php` migration + rollback-tested.

### 2. Unified Content Calendar with Drag-and-Drop Scheduling
| Field | Value |
|-------|-------|
| **RICE Score** | **280** |
| **Reach** | 9 (all content creators) |
| **Impact** | 3 (core daily workflow) |
| **Confidence** | 90% (models exist, UI needed) |
| **Effort** | 1.0 PM |

**Why Now:** Competitors (Hootsuite, Buffer, Later) have this as table-stakes. Current post-by-post scheduling is friction-heavy. Agency teams need visual calendar to plan weeks ahead.

**Technical Approach:**
1. **Frontend** — FullCalendar.js or Vue Calendar component with drag-and-drop, week/month views, color-coded by platform
2. **Backend** — Extend `SocialPost` with `calendar_slot` metadata. API endpoint `/api/v1/calendar?from=&to=` returning posts grouped by date
3. **Bulk move** — Drag 10+ posts to reschedule; queue `BulkScheduleService` (already exists) for batch update
4. **Smart slot suggestion** — Use `OptimalPostingTime` model + `SmartSchedulingService` to highlight green/yellow/red time slots
5. **Conflict detection** — Warn if same account scheduled within 30-min window
6. **Recurring posts** — "Repeat weekly/monthly" using Laravel task scheduler

**User Impact:** Reduces scheduling time by ~70%. Agency admins can plan 2-4 weeks of content in <30 min. Differentiator for enterprise trials.

**Deliverable:** `/calendar` view, `CalendarController`, `calendar.blade.js`, 12+ E2E tests.

### 6. Workflow Automation Builder (Visual Flowchart)
| Field | Value |
|-------|-------|
| **RICE Score** | **120** |
| **Reach** | 6 (power users, enterprise) |
| **Impact** | 3 (10x automation capability) |
| **Confidence** | 80% (engine exists, UI missing) |
| **Effort** | 1.5 PM |

**Why Now:** `WorkflowEngine`, `WorkflowTemplate`, `WorkflowVersion`, `WorkflowExecution`, `WorkflowLog` models exist but require JSON/API configuration. No-code visual builder is the #1 requested enterprise feature. Competitors (Zapier, Make) win on visual workflow UX.

**Technical Approach:**
1. **React Flow / Vue Flow** — Drag-and-drop node editor for triggers → conditions → actions
2. **Node types** — Trigger (schedule, webhook, post-published), Condition (if/else, threshold), Action (post, email, notify, AI-analyze)
3. **Template library** — Pre-built workflows from `WorkflowTemplate` seeds: "Auto-reply to comments", "Weekly report digest", "Churn-risk client alert"
4. **Version control** — Use `WorkflowVersion` model for rollback, diff view
5. **Test mode** — Dry-run workflow with sample data before activation
6. **Webhook trigger builder** — Auto-generate webhook URL per workflow node

**User Impact:** Enterprise deal enabler. Reduces workflow setup from hours to minutes. Drives AI credit usage (each node call consumes credits).

**Deliverable:** `/workflows/builder`, `WorkflowBuilderController`, `workflow-builder.vue`, 15+ test workflows.

### 9. A/B Testing Engine for Content
| Field | Value |
|-------|-------|
| **RICE Score** | **72** |
| **Reach** | 5 (content strategists) |
| **Impact** | 2 (data-driven content) |
| **Confidence** | 70% (partial foundation) |
| **Effort** | 1.0 PM |

**Why Now:** `AbTest`, `AbTestLog` models exist but are stubs. Agencies need to test headlines, CTAs, visuals. Competitor gap: Sprout Social has A/B testing; we don't.

**Technical Approach:**
1. **Test creator** — Select post, define variant B (different text/image/CTA), set traffic split (50/50, 80/20)
2. **Auto-rotation** — Schedule both variants, track engagement via `TrackingService`
3. **Statistical significance** — Calculate winner at 95% confidence; auto-declare winner
4. **Auto-promote winner** — Winner variant gets 100% traffic
5. **Test history** — Dashboard of all past tests with learnings extracted by `PredictiveAnalyticsEngine`

**User Impact:** Premium feature for Pro→Enterprise upsell. Agencies using A/B testing retain 30% longer (industry benchmark).

**Deliverable:** `/ab-tests` module, `AbTestController`, statistical engine (PHP-ML or simple z-test), 10+ tests.

## ⚠️ Risks & Mitigations

| Risk | Probability | Mitigation |
|------|-------------|------------|
| FK constraint fix breaks existing orphan data | Medium | Migration runs `DELETE orphans` with dry-run flag first |
